Metafields

Metafields give every product its own color, cutout, texts and images. This page lists the metafields Balm Studio reads, with the exact name, key and type to create.

Before you start

The theme cannot create a metafield definition; only you can, in your admin. This is a platform rule: a setting can only be connected to a definition that already exists, with the right type. So the definition always comes first, the connection second, the values third.

  • Definitions are created in Settings, Custom data, under Products, Collections, Pages or Shop, depending on what carries the value.
  • Type the Name exactly as listed below. The admin derives the key from the name, in lowercase with underscores, so the key matches on its own. If you rename a definition, check its key before saving: the connection works by key.
  • Names are shown in quotation marks here and in the theme editor so you can see where they start and end. The quotation marks are not part of the name.
  • The namespace and key are suggestions; the type is not. A setting refuses a definition of the wrong type.
  • Every connectable setting repeats the definition it expects in its own help text in the editor.

Product color

Balm Studio dresses every page in the color of the product it shows. Each product needs two colors, a dark one and a light one; the theme works out the grounds and the texts of the page from them and checks their contrast. The theme reads these keys directly: create the definitions once, then fill the values on each product. There is nothing to connect in the theme editor.

NameNamespace and keyTypeWhere it showsWithout a value

Next productcustom.next_productProduct (one value)Next formula on the product page.The next product of the primary collection, else nothing.

The same two colors can be set on a variant (custom.background_color, custom.background_color_end and custom.cutout, under Settings, Custom data, Variants): choosing that variant on the product page recolors the page. A variant without them uses the color of its swatch, then the product's. On a collection, the same two color keys (under Settings, Custom data, Collections) give the collection page its color; without them, the color of the first product.

  1. In Settings, Custom data, Products, choose Add definition. Name Background color, namespace and key custom.background_color, type Color. Save.
  2. Repeat with Background color end (custom.background_color_end, Color), Cutout (custom.cutout, File, images only), Name lines (custom.name_lines, Single line text), Volume (custom.volume, Single line text) and Next product (custom.next_product, Product, one value).
  3. Open a product, scroll to its Metafields card and fill the values: a deep color and a light color of the same hue work best.
  4. Open the product on your store: the page, the header and the tile wear its color.

Article product

A blog article metafield, Product (custom.product, type Product, one value, under Settings, Custom data, Blog posts), links an article to one product. The Journal and Journal article sections then paint the article in that product's color and show the product at the end of the article. Without it, the article uses the house pair.

Metaobjects

Balm Studio reads no metaobject: there is nothing to create under Settings, Custom data, Metaobject definitions. The Ingredient atlas is built from its own Ingredient blocks, each with a name, a note and the products that contain it.

Badge label, step by step

  1. In your admin, open Settings, then Custom data, then Products.
  2. Choose Add definition.
  3. Name: Badge label. Check that the namespace and key read custom.badge_label.
  4. Select the type Single line text (under Text), keep One value, and save.
  5. Open a product, find the Metafields card, type the badge text in Badge label, for example Limited edition, and save.

The badge now shows wherever that product appears as a card, in quick view and in Compare products. On the product page it shows when Badges on media is on Automatic or a Badge block is in the column. Its colors are in Theme settings, Product badges, unless the product has its own (below). Clear the value and the badge goes.

Badge colors, step by step

Optional: only for products whose Custom badge should not wear the colors of Theme settings.

  1. In Settings, Custom data, Products, choose Add definition. Name: Badge color, namespace and key custom.badge_color, type Color. Save.
  2. Choose Add definition again. Name: Badge text color, namespace and key custom.badge_text_color, type Color. Save.
  3. Open a product that has a Badge label, and in its Metafields card pick a Badge color, for example a deep green. Pick a Badge text color too, or leave it empty.

With only the badge color, the text is picked for you: the text color or the background color of Scheme 1, whichever contrasts more with the badge, or pure black or white when neither reaches 4.5:1. With only the text color, the text sits on the Custom background of Theme settings. Create both as Color: a value that is not a color, such as a word typed in a text metafield, is ignored. The two colors apply to the Custom badge only, never to Sale, Sold out or New, and not to the Spinning badge, which keeps the colors set in its block.

Primary collection, step by step

Optional: for products that sit in several collections, to choose the one the breadcrumb trail shows.

  1. In Settings, Custom data, Products, choose Add definition. Name: Primary collection, namespace and key custom.primary_collection, type Collection (under References), one value. Save.
  2. Open a product, and in its Metafields card pick the collection in Primary collection.
  3. Check that Show breadcrumbs and Show the collection are on in Theme settings, Breadcrumbs.

A visitor who arrives from a collection grid still sees that collection in the trail; the metafield decides for the others, such as a visitor coming from a search engine. Search engines read the same trail.

Banner image, step by step

Optional: for collections whose banner needs another picture than the collection image, or a precise framing.

  1. In Settings, Custom data, Collections, choose Add definition. Name: Banner image, namespace and key custom.banner_image, type File, with images accepted. Save.
  2. Open a collection in Products, Collections, and in its Metafields card pick the picture.
  3. To control the framing, set the focal point of the picture in Content, Files.

The banner takes, in this order, this metafield, the Banner image of the Collection section, then the collection's own image. Shopify keeps no focal point on a collection's own image, which is why the metafield and the section setting exist.

Page image, step by step

Optional: for pages linked from the main menu, so their link shows a picture in the dropdowns and in Image cards.

  1. In Settings, Custom data, Pages, choose Add definition. Name: Image, namespace and key custom.image, type File, with images accepted. Save.
  2. Open a page in Online Store, Pages, and pick its picture in the Metafields card.

A page without it shows its link without a picture, and an Image cards block set to Automatic leaves it out.

Tagline, step by step

  1. In Settings, Custom data, Products, choose Add definition.
  2. Name: Tagline, namespace and key custom.tagline, type Single line text. Save.
  3. Fill it on each product, for example Rich overnight repair for dry skin.
  4. The default product template already has a Text block with Source set to Tagline under the title. On another template, add a Text block and choose that source.

A product without a tagline shows nothing there, not even the space of the line. In the theme editor, a dimmed example stands in so you can place and size the block.

Icon metafields, step by step

The Icon list of the product page holds up to three claims, each an Icon item block, and each claim can come from the product: an icon picture and a line of text per item, numbered by item. Create the ones you need:

NameNamespace and keyTypeWhere it shows
Icon image 1, Icon image 2, Icon image 3custom.icon_image_1 to custom.icon_image_3File (image)The Icon image of the first, second and third Icon item. A picture keeps its proportions and sits on the bottom of its box.
Icon text 1, Icon text 2, Icon text 3custom.icon_text_1 to custom.icon_text_3Single line text, or Multi-line textThe Heading (or the Text) of the first, second and third Icon item. Each line of a Multi-line text shows on its own line. The same metafields can feed Claim 1 text to Claim 4 text of a Products showcase spotlight, read on the spotlight's product.
  1. In Settings, Custom data, Products, add the definitions: for example Icon image 1, type File, and Icon text 1, type Multi-line text (or Single line text for one line).
  2. Fill them on each product, for example a leaf picture and Vegan formula.
  3. In the theme editor, open a product, select the first Icon item of the Icon list, then next to Icon image select the dynamic source icon and pick Icon image 1. Do the same next to Heading with Icon text 1. Repeat for the second and third items.

These names and keys are suggestions: any key works, as long as the type matches, since you connect them yourself. An item whose heading and text both come back empty stays hidden on the storefront and leaves no gap; in the theme editor it keeps a small badge that says why.

Product list metafields

The Products setting of the Product upsell block, of the Complementary products block and of the cart drawer suggestions can be connected to a product metafield of type Product, set to accept a list of products. Each product then carries its own hand picked selection, for example Upsell products with the key custom.upsell_products. The block's Products come from setting must be on A manual selection.

Review metafields

The Rating block, the ratings on product cards, in quick view and in Compare products read Shopify's standard review metafields, reviews.rating (Rating) and reviews.rating_count (Integer). Review apps fill them; you have nothing to create. Until they are filled, the ratings stay hidden.

Compare products rows

Compare products has no metafield of its own. Each Row block with Source set to Metafield reads the product metafield you name in its Metafield setting, on every compared product, so you decide which facts the table compares. Type the metafield's name, exactly as it shows in Settings, Custom data, Products (Skin type), or its key (custom.skin_type). A name is turned into the key the admin gives it by default: namespace custom, the name in lowercase with underscores. If you changed the key of a definition, type the key.

The field takes no dynamic source on purpose: a connected metafield would give the value of the page's product in every column. To name the row after the metafield, connect it to the row's Label instead, or leave Label empty to show the name you typed. For example, to compare three creams of a range:

NameNamespace and keyTypeWhere it showsHow to create it
Texturecustom.textureSingle line textA Row block with Metafield Texture. Each product shows its value, for example Rich balm or Light gel.Settings, Custom data, Products, Add definition: name Texture, type Single line text, one value.
Skin typecustom.skin_typeSingle line text, or a listA Row block with Metafield Skin type, for example Dry to very dry. A list of values reads as a sentence.Settings, Custom data, Products, Add definition: name Skin type, type Single line text.
Fragrance freecustom.fragrance_freeTrue or falseA Row block with Metafield Fragrance free: a check mark for true, a cross for false.Settings, Custom data, Products, Add definition: name Fragrance free, type True or false.
Volumecustom.volumeVolume, or IntegerA Row block with Metafield Volume. A volume, weight or dimension carries its unit; for a plain number, type the Unit of the row, such as ml or %.Settings, Custom data, Products, Add definition: name Volume, type Volume.
  1. Create one definition per fact, as in the table. These names and keys are examples: any name works, as long as the row names the same metafield.
  2. Fill the values on each product you compare, in the Metafields card of the product.
  3. In the theme editor, open the Compare products section and add one Row block per fact. Keep Source on Metafield, type the name or the key in Metafield, and a Label if the left column should read differently.

Every metafield type is drawn as such: true or false as icons, a list as a sentence, a number with the row's unit, rich text and multi-line text with their lines, a money amount, a rating out of its scale, a color with its swatch, an image, and a reference (a product, a collection, a page) by its title. A product without a value shows a hyphen, read as n/a by screen readers. In the theme editor, a row whose metafield none of the compared products has says so, so you can fix the name.

The other sources need no metafield: Vendor, Product type, Tags, SKU, Barcode, Weight and Unit price read the product's own fields. The rating row reads the review metafields (see Review metafields).

What happens on a product with no value

Nothing breaks and nothing goes blank, which is what lets you fill only the products you care about. A background color that comes back empty falls through, in this order:

  1. the Fallback background color setting, if you set one;
  2. otherwise the background of the section's color scheme.

In a Products showcase spotlight and in Featured set, the order is the override field, then the product's metafield, then the background of the section's color scheme. In the Product gradient mode of the product page, one color alone paints a flat background and no color leaves the color scheme; the fallback color is not used there. For the Custom badge, an empty custom.badge_color or custom.badge_text_color leaves the Custom colors of Theme settings. Behind cutout images, an empty tagline shows no text, and an empty custom.background_color_end gives the text the scheme text color.

Never connect the fallback color itself to a metafield: it is the safety net. If one end of a gradient is empty, the other end fills the whole wash; if a halo color is empty, the halo is not drawn and the base color stays. An empty text, rich text or image metafield shows nothing on the storefront: never an example text, never an empty box. The tagline, a popup, an accordion row, a claim line, a specification row, the rating and the badges hide themselves and leave no gap. In the theme editor a dimmed example stands in.

Settings that cannot be connected

Shopify only allows connections on colors, text, rich text, images, videos, links, pages, collections, products and metaobjects. Sliders, checkboxes, dropdowns, the color scheme and Liquid code are fixed for the whole template. When one product needs a different value for one of those, give it a second product template.
